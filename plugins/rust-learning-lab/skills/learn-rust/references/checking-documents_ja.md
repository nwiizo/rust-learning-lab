# ソースと出力の引用を検証する

[English](checking-documents.md) | 日本語

学習文書のソース引用、実行結果、意図的な失敗例を繰り返し検証したいときに使う。
通常のプロジェクト例には、既存のCargoテストやrustdocを優先する。
任意で使えるRust CLI `rust-learning-check` は、標準ライブラリを使う単独のプログラムに対応する。
別に管理するツールであり、このプラグインには同梱せず、自動インストールもしない。
利用できるローカルのチェックアウトか実行ファイルを使い、存在を仮定しない。

## 検証内容を指定する

設定ファイル、文書、ソースを一つのディレクトリ内に置く。Markdownのマーカーを含め、
すべてのパスを設定ファイルのディレクトリから指定する。
正常に動く例と、意図的に失敗する対比例の設定は次のようになる。

```toml
version = 1
edition = "2024"
documents = ["lesson.md"]

[[examples]]
id = "borrowed"
path = "borrowed.rs"
kind = "run"

[[examples]]
id = "moved"
path = "moved.rs"
kind = "compile-fail"
error_codes = ["E0382"]
corrected = "borrowed"
```

例のEditionを指定し、対応するコンパイラを使う。コードフェンスの前に
`<!-- rlc:source borrowed.rs -->` を置くと、ソースの連続する完全な行と照合する。
`<!-- rlc:stdout borrowed -->` は出力全体との照合に使う。もう一方の出力には `stderr` を使う。
失敗例のstderrには、人が読むためのコンパイラ診断文を使う。
出力は実際の実行から転記し、省略した例は省略を明記してマーカーを付けない。
CRLFとLFは同じと扱い、出力の末尾の改行を1つ無視するが、それ以外の空白は保つ。
マーカー付きのブロックが最低1つ必要。同じエラーコードが別の式で発生する場合もあるので、
コードだけでなく診断の位置も確認する。

## 実行して結果を伝える

インストール済みなら `rust-learning-check check checks.toml` を実行する。
CLIのローカルチェックアウトなら、
`cargo run --locked --manifest-path <cli-checkout>/Cargo.toml -- check <checks.toml>` を使う。
両方の仮置きのパスを実際のパスに置き換える。CLIのビルドにはRust 1.90以降が必要で、
macOSとLinuxに対応する。`RUSTC` でコンパイラの実行ファイルを選べる。
表示されたコンパイラの版とEditionを結果に添える。

CLIは実行前に参照とソース引用を照合する。実行する例では正常終了を、失敗例では
エラーコードの集合の一致と修正版の正常動作を確認する。出力は部分一致ではなく全体を照合する。
stdoutが一致しても、終了コードが非0なら失敗になる。
既定の制限はプロセスごとに30秒、出力ごとに1 MiB。
制限はコードを隔離するものではなく、プログラムは呼び出し元の環境とアクセス権を引き継ぐため、
信頼する例だけを実行する。終了コードは0が成功、1が検証の失敗、2がCLI引数の誤り。
最初の失敗で止まるため、それ以前のPASSは途中までの結果として扱う。

CLIがない場合やCargoの依存・featureが必要な例では、既存のツールチェーンを使い、
ソースと出力を直接照合する。実行した内容と、読んで確認した内容を分けて伝える。
マーカーのない本文、図の意味、全入力での動作の同等性、学習効果は検証の対象外になる。
ほかの根拠の選び方は[判断と根拠を結び付ける説明](verified-explanations_ja.md)を使う。
