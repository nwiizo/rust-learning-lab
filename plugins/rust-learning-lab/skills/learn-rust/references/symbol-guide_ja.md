# Rustの記号ガイド

[English](symbol-guide.md) | 日本語

記号の一覧を求められたときや、見慣れない記号がコードを読む妨げになっているときに使う。
よく使うRustの記法を扱い、文法の全規則や個々のマクロ独自の構文まで網羅するものではない。
名称は調べる手がかりにし、その位置での役割、何の役に立つか、小さな比較を説明する。
動かせる対比例は[実行できる説明例](worked-examples_ja.md)を使う。表中の例は構文の断片であり、
単独で実行するプログラムではない。全項目の暗記を求めず、関係する行を選ぶ。

## 1. まとまり・区切り・名前の指定

| 記法 | この場所ではどう読むか | 役割と比較のポイント |
|---|---|---|
| `(…)` | `f(x)` は呼び出し、`(x + y)` は式のまとまり、`(x, y)` はタプルの生成 | 括弧だけで呼び出しとは決まらない。直前の部分と中のカンマを見る |
| `()` / `(x,)` | ユニット値・型／要素が一つのタプル | `()` は追加の値を持たない。`(x,)` はタプルだが、`(x)` は `x` を括弧で囲んだだけ |
| `{…}` | `if ok { 1 } else { 0 }` のブロック、`Point { x: 1, y: 2 }` の名前付きフィールド | ブロックは値を返せる。構造体の式は値を組み立てる。`use path::{A, B}` ではインポートをまとめる |
| `[…]` | `[1, 2]` は配列の生成、`values[i]` は添字によるアクセス | `[T; N]` は配列型、`[T]` はスライス型。位置で生成・アクセス・型を区別する |
| `[value; N]` | 要素を繰り返して長さ `N` の配列を作る | `[0; 3]` は0が三つで、`[0, 3]` とは異なる。`Copy` でない要素には制限があり、任意の値をcloneする記法ではない |
| `,` | 引数・フィールド・要素・matchの分岐を区切る | 末尾にも書ける場合が多い。`(x,)` ではタプルと式のまとまりを区別する |
| `;` | 文を終える。配列の記法では要素と長さを区切る | `{ compute(); }` は計算した値を捨てて `()` を返し、`{ compute() }` はその値を返す |
| `:` | `value: Type` は型注釈、`T: Trait` は制約、`Point { x: 1 }` はフィールドの指定 | 束縛と型、型と制約、フィールドと値のどれを結んでいるか示す |
| `::` / `.` | `std::mem::size_of` はパス、`value.len()` はメソッド呼び出し、`pair.0` はタプルのフィールド参照 | `::` は名前のある項目を選び、`.` は値を使う。記号だけで関数を呼ぶかどうかは決まらない |
| `->` / `=>` | `fn f() -> u32` は戻り値の型、`Some(x) => x` はパターンと式の対応 | 型の宣言と評価する式の選択を区別する。矢印自体が `return` を実行するわけではない |

## 2. 参照・型・パターン

| 記法 | この場所ではどう読むか | 役割と比較のポイント |
|---|---|---|
| `&` / `&mut` | `&value` / `&mut value` は借用、`&T` / `&mut T` は参照型 | 所有権を受け取らずに値へアクセスする。共有アクセスと変更を許す排他的なアクセス、束縛の `mut` を区別する |
| `*` | `*r` は参照先をたどる。`*const T` / `*mut T` は生ポインタ型 | 参照先へのアクセスやポインタの種類を表す。乗算とは別の使い方で、参照外しが自動的なcloneになるわけではない |
| `'a` / `'static` / `'_` | 名前を付けたライフタイム、静的なライフタイム、推論するライフタイム | 有効期間の関係を示し、値の寿命を延ばす指示ではない。`T: 'static` は所有する値を永久に生存させる要求ではない |
| `'label:` / `break 'label` | ループやブロックに名前を付け、抜ける場所を選ぶ | 処理の行き先を制御する。このアポストロフィは借用の注釈ではない |
| `<…>` / `::<…>` | `Vec<u8>` は引数を指定した型、`parse::<u32>()` は式の中での引数指定 | ジェネリックな型や処理を具体化する。実行時の引数や大小比較と区別する。型だけでなくライフタイムや定数も引数になり得る |
| `<T as Trait>::Item` | `T` の `Trait` を通して `Item` を選ぶ | 短い書き方では曖昧になる関連項目の参照先を明示する |
| 制約の `+` / `?` | `T: Read + Send` は両方を要求し、`T: ?Sized` はコンパイル時にサイズが分からない型も許す | 条件を組み合わせたり、暗黙の `Sized` 要求を緩めたりする。加算や失敗の伝播とは異なる |
| `'a: 'b` / `T: 'a` | ライフタイム同士の有効期間の関係、型に対するライフタイムの制約 | 有効性の条件を表す。`T` 内の参照を説明し、`T` の値すべてを保持し続ける指示とはしない |
| `_` | `Some(_)` では値を束縛しない。`Vec<_>` では型を推論する | 不要な値への命名や分かっている型の明記を省く。`_name` は値を束縛し、所有権を移す場合もあるため、ワイルドカードの `_` と異なる |
| `@` | `n @ 1..=5` は範囲を確かめながら値を束縛する | 値全体を `n` として使えるようにしつつ、一致する条件を指定する |
| パターンの `\|` | `A \| B` はどちらかのパターンに一致 | 候補をまとめる。クロージャの引数を囲む縦棒や、値への演算子とは異なる |
| パターンの `&` | `let &n = reference;` は参照に照合する | 既存の参照を分解する。`&value` のように新しく借用する式ではない。束縛の動作はパターンと型によって決まる |

照合と束縛の詳しい動作は[パターンの仕様](https://doc.rust-lang.org/reference/patterns.html)を参照する。

## 3. 演算・範囲・処理の流れ

| 記法 | この場所ではどう読むか | 役割と比較のポイント |
|---|---|---|
| `=` | `let n = 1` は初期化、`n = 2` は代入 | 値を設定する。`==` は比較。`type Count = u32` は別名の定義で、実行時の代入ではない |
| `+` `-` `*` `/` `%` | 算術演算。`%` は余り、先頭の `-x` は符号の反転 | 値を計算する。整数の除算と浮動小数点数の除算は異なる。独自の型では演算子の実装を確認する |
| `+=` `-=` `*=` `/=` `%=` | 計算して左辺に代入する | 対象を更新する。展開して説明するとき、複雑な左辺を機械的に二回評価しない |
| `==` `!=` `<` `<=` `>` `>=` | 等しさや大小の比較 | 真偽値を返す。ジェネリック引数の `<` と `>` は区切り記号になる |
| `&&` `\|\|` | 短絡評価する論理AND・OR | 左辺で結果が決まれば右辺を評価しない。右辺の副作用も実行されない場合がある |
| `!` / `&` / `\|` / `^` | 反転・AND・OR・XOR | 整数ではビット単位の演算。真偽値の `!` は真偽の反転で、真偽値の `&`・`\|`・`^` は短絡評価しない |
| `<<` `>>` / `&=` `\|=` `^=` `<<=` `>>=` | ビットシフト、ビット演算と代入 | ビットを操作する。`Vec<Vec<u8>>` の `>>` は入れ子のジェネリック引数を閉じる記号になる |
| `a..b` / `a..=b` | 終端を含まない範囲／含む範囲 | 境界を明示する。整数の `0..3` は0・1・2、`0..=3` は3も含む |
| `..b` `..=b` `a..` `..` | 片側または両側の境界を省いた範囲 | スライスの切り出しなどに使い、`&values[..]` は全体を借りる。どの形・型の範囲でもそのまま反復できるわけではない |
| パターン・構造体の式の `..` | `Point { x, .. }` は他のフィールドを無視し、`Point { x: 1, ..old }` は残りを `old` から受け取る | 必要な部分だけ照合したり、フィールドを再利用したりする。構造体の更新では非 `Copy` フィールドの所有権が移り得るため、自動的なcloneとはしない |
| `\|x\| 式` / `\|\| 式` | 引数が一つ／引数なしのクロージャ | 周囲の変数も捕捉できる処理を渡す。空の引数部分は論理ORではない |
| 式の後の `?` | 成功なら中身を取り出し、失敗なら囲んでいる関数・クロージャから返す | `Result` は `Ok` で継続し、エラーを返す。`Option` は `Some` で継続し、`None` を返す |
| 戻り値の型の `!` | `fn stop() -> !` は通常の戻り方をしない | 抜けないループなど、戻らないことを表す。エラー値を返すという意味ではない |
| `...` | 古い包含範囲パターン、または外部関数の宣言での可変長引数 | 一般的な省略や展開の演算子として教えない。現在の包含範囲パターンには `..=` を使う。外部関数の可変長引数には別の制限がある |

評価や型ごとの規則は[演算子の仕様](https://doc.rust-lang.org/reference/expressions/operator-expr.html)を参照する。

## 4. マクロ・属性・コメント

| 記法 | この場所ではどう読むか | 役割と比較のポイント |
|---|---|---|
| `name!(…)` / `name![…]` / `name!{…}` | マクロを呼び出す | 受け付ける入力はマクロが決める。括弧の変更や通常の関数への置き換えが常に同等とは限らない |
| `$name` / `$name:expr` / `$crate` | マクロのメタ変数、式の捕捉、マクロを定義したクレート | `macro_rules!` で構文を照合・再利用する。`$` は通常の文字列の変数展開ではない |
| `$(…)*` / `$(…)+` / `$(…)?` | マクロの規則で0回以上・1回以上・0回か1回 | 構文の繰り返しを照合・展開する。`$($item:expr),*` のカンマは繰り返しの区切り。`*`・`+`・`?` はマクロ内での役割になる |
| `macro_rules!` の `=>` | 照合する形と展開内容を区切る | 構文の変換を定義する。matchの分岐と異なり、実行時の分岐ではない |
| `#[…]` / `#![…]` | 次の項目に付く属性／囲んでいる項目に付く属性 | `#[test]` や `#![allow(dead_code)]` などの指示を付ける。`#` はRustの行コメントではない |
| `//` / `/* … */` | 行コメント／ブロックコメント | 実行せずにソースを説明する。ブロックコメントは入れ子にできる |
| `///` / `/** … */` | 次の項目のドキュメントコメント | 通常のコメントと異なり、API文書の生成に使われる |
| `//!` / `/*! … */` | 囲んでいる項目のドキュメントコメント | 次の関数ではなく、モジュールやクレート自体の説明などに使う |

詳しくは[マクロの規則](https://doc.rust-lang.org/reference/macros-by-example.html)、
[属性](https://doc.rust-lang.org/reference/attributes.html)、[コメント](https://doc.rust-lang.org/reference/comments.html)を参照する。

## 5. リテラルと接頭辞

| 記法 | この場所ではどう読むか | 役割と比較のポイント |
|---|---|---|
| `'x'` / `"text"` | 文字／文字列リテラル | `char` はUnicodeスカラー値で、文字列リテラルは `&'static str` 型。ライフタイム名には閉じる引用符がない |
| `\n` `\r` `\t` `\\` `\0` `\'` `\"` | 対応するリテラル内のエスケープ | 改行・復帰・タブ・バックスラッシュ・NUL・引用符を、区切りと混同せずに書く |
| `\xNN` / `\u{…}` | リテラルの種類に応じたバイト・ASCII・Unicodeのエスケープ | 値を数値で指定する。文字・バイト・文字列で、使えるエスケープと範囲が異なる |
| `r"…"` / `r#"…"#` | raw文字列リテラル | バックスラッシュをそのまま扱う。前後の `#` の数を揃えると、内容に引用符も含められる。属性ではなく区切りになる |
| `b'x'` / `b"…"` / `br#"…"#` | バイト・バイト文字列・rawバイト文字列 | Unicodeの文字ではなくバイトを表す。`b'x'` は `u8`、バイト文字列はバイト配列への参照 |
| `c"…"` / `cr#"…"#` | C文字列／raw C文字列リテラル | Cとの連携に使う `CStr` への参照を作る。対象ツールチェーンの対応と、内容にNULを含められない制限を確認する |
| `1_000` / `42u8` / `1.0f32` | 桁の区切り／数値型の接尾辞 | 読みやすくしたり数値の型を決めたりする。この `_` はパターンや値の欠落ではない |
| `0xFF` / `0o77` / `0b1010` / `1e3` | 16進・8進・2進・浮動小数点数の指数表記 | 数値の書き方を指定する。別の算術演算子ではない |
| `r#type` | raw識別子 | 許される位置でキーワードを名前として使う。`r#"…"#` と違い、文字列ではない |
| 書式文字列の `{}` / `{:?}` / `{name}` | `format!("{name}")` などの埋め込み位置や書式指定 | Rustのブロックではなく書式のための記法。`{{` と `}}` は波括弧自体を表示する。対応する表示方法は書式用のトレイトによって決まる |

リテラルは[トークンの仕様](https://doc.rust-lang.org/reference/tokens.html)、raw識別子は
[識別子の仕様](https://doc.rust-lang.org/reference/identifiers.html)、埋め込み位置は
[書式指定の仕様](https://doc.rust-lang.org/std/fmt/index.html)で確認する。

## 記号の形から、関係と変化へ読む

記法が意味を持つ理由や、何の役に立つかを深く知りたい場合に使う。
記号が指す対象、式の中での役割、式を評価した結果を結び付ける。
この考え方を学習者のコードへ直接使い、記号論の用語を知らなくてもRustの説明を理解できるようにする。

### 一つの記号が、何と何を結ぶかを示す

`fn first<'a>(left: &'a str, right: &str) -> &'a str` を、アポストロフィごとに訳す前に、入力と出力の関係として読む。
同じ `'a` が、返す参照の有効期間と最初の入力を結んでいる。名前をすべて `'text` に変えても、その関係は変わらない。
同じように、`&value` と値を所有権ごと渡す場合、`&T` と `&mut T` を比べる。
呼び出し側で何を使い続けられるか、呼び出された側で何ができるかを追うと、記法の実用上の価値が見える。
[ライフタイムの例](worked-examples_ja.md#a-は返す参照と入力の関係を表す)では、注釈が所有者の寿命を延ばすという説明をせずに、その関係を追っている。

文脈で役割が変わるといっても、読み手が好きな意味を選べるわけではない。Rustの文法と型が役割を決める。
`*r` なら `r` の参照先を確認し、`a * b` なら対象の型と乗算の実装を確認する。
文脈から読むことを、型の合ったプログラムを自由に解釈し直せるという話にはしない。

### 値を表すことと、状態を変えることを分ける

`x = x + 1` の右辺は更新前の値を読んで新しい値を計算し、左辺は書き込む先を指定する。
ある数とそれに1を足した数が等しい、という等式ではない。更新前と更新後を追ったうえで、
等しさを調べる `x == x + 1`、新しい束縛を作る `let x = x + 1` と比べる。
「代入」「シャドーイング」という用語を覚えさせるだけで終えず、[動かせる対比例](worked-examples_ja.md#代入とシャドーイングを時間の順に読む)を使う。
これはRustの[代入の規則](https://doc.rust-lang.org/reference/expressions/operator-expr.html#assignment-expressions)に沿った説明であり、
代入が再帰関数の実行だという主張ではない。

### 型・等しい値・同じ対象を区別する

`let name: String = String::from("Rust")` の `String` は型を表し、`name` は特定の値に付く名前、
`String::from("Rust")` は値を作る式。同じ「記号」として一括りにする前に、それぞれの役割を示す。
Rustの[場所を表す式と値を表す式の規則](https://doc.rust-lang.org/reference/expressions.html#place-expressions-and-value-expressions)を手がかりに、
どの場所へアクセスし、その値を読む・コピーする・移すのかを説明する。

`let other = name.clone()` とした場合、`name == other` が真でも、二つの文字列は別々に所有される。
一方、`let borrowed = &name` では参照を通して `name` にアクセスする。
内容が等しいこと、別々に所有すること、同じ対象を借りることは、それぞれ別の話。
関数に同じ文字列を読ませられる場合でも、`&name` を `name.clone()` に変えると所有権や費用が変わる理由へつなげる。
名前・値・メモリアドレスを同一視せず、ポインタが等しいことをあらゆる対象の同一性の定義にしない。

### 部分を組み合わせて、全体の意味を作る

`Option<&'a str>` は、文字列データを表す `str`、`'a` の間有効な参照を表す `&'a str`、
その参照がある場合とない場合を区別する `Option<…>` と、層を追って読む。
`text.parse::<u32>()?` なら、変換先の型を選び、メソッドを呼び、数値を使って先へ進むかエラーを返す、という順に読む。
途中の型に名前を付けると、記号が処理の周りの飾りではなく、全体を説明するために必要な部分として見えてくる。

周囲の条件から部分を読むこともある。`let values: Vec<u32> = source.collect()` では、代入先の型が
`collect()` の作る型を決める手がかりになる。記号を左から一つずつ訳すだけでは全体を読み取れない。
部分の組み合わせに加えて、関数の宣言、期待される型、後続の使用がその式に与える条件をつなげる。
型推論が実行後に動作を変えるかのようには説明しない。

この組み合わせ、関数の再帰呼び出し、広い意味での自己言及は区別する。
型が入れ子になっただけで自己言及になるわけではなく、`&` の参照が自分自身を指す必要もない。ライフタイムのパラメータも再帰ではない。
これは説明を組み立てる見方であり、それだけで学習効果が実証されたり、現在のコンピュータやAIが何を理解できるかが確定したりするわけではない。
