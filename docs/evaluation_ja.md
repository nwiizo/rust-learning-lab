# 対話の確認課題

[English](evaluation.md) | 日本語

リリース前や指示変更後に、対象ホストの新しい会話で試すための課題。
以下は期待する動作であり、実施済みの評価結果ではない。回答の見出しや文言の一致は採点しない。
ホスト・モデル・プラグイン版・入力・回答・使ったツールを残し、仕様説明の正しさと依頼への適合を確認する。
ファイル変更を伴う課題には一時的な学習用ディレクトリを使う。

| 入力例 | 観察する動作 | 問題となる動作 |
|---|---|---|
| `fold(10, \|acc, item\| acc - item)` の引数順はなぜ？ | 外側の初期値とクロージャの引数を区別し、役割と具体値を追う。設計意図は根拠がなければ推測とする | 引数名だけで役割を決める、加算の例だけで交換可能と説明する |
| `String` を関数へ渡した後のE0382を説明して | 値渡しと借用を対比し、呼び出し後の利用意図から修正を選ぶ | 常にcloneを禁止、すべての借用エラーを実行時の危険と断定 |
| `?` を最短で説明して | 成功時の値と失敗時の戻り先を必要な範囲で答える | 講義や小テストを必須にする |
| ヒントだけで数値文字列の合計を練習したい | 入力・失敗時の動作を確認し、必要なヒントの後に回答を待つ | 完成コードをすぐ出す、期待値を出力に合わせる |
| AIが書いた関数はテストが通った。もう理解したと言える？ | 動作と理解を分け、別条件の予測や説明で確かめる方法を示す | 合格だけで習得済みと判定、AI利用を一律禁止 |

## 記号が読みづらい場合の確認

各入力を別々に試す。名称を答えただけでなく、意味・実用上の価値・具体的な比較があるかを見る。

| 入力例 | 観察する動作 | 問題となる動作 |
|---|---|---|
| `&` や `'a` が読めない。`fn first<'a>(left: &'a str, right: &str) -> &'a str` を説明して | 所有者と返す参照を最初の入力に対応づけ、入力が一つで省略できる宣言と、二つあるこの宣言を比べる | 注釈で寿命が延びる、所有者の寿命が同じになる、注釈は常に必須と説明 |
| `let r: &mut i32 = &mut n; *r += 1;` の `*` は何のため？ 掛け算？ | 参照先の整数を変更する流れを示し、束縛のmut・可変参照・乗算を区別する | 「参照外し」だけで終える、`mut r` を必須にする、`*` は常にコピーやcloneだと説明 |
| `std::num::ParseIntError` と `text.parse::<u32>()?`、matchで書いた場合の `->` と `=>` を説明して | パス・型引数・実行時の引数を分け、型推論、成功と失敗の両経路、何がreturnするかを示す | `::` を呼び出しとする、型引数を常に必須とする、矢印を混同、エラーを黙って捨てる |
| `fold(10, \|acc, item\| acc - item)` の縦棒は何のため？ | 処理を渡す意味、各引数を渡す側、タプルへの置き換えで意味が変わる理由を説明する | 「クロージャ」という名称だけで用途を説明しない、縦棒をORと説明 |
| `assert!(!ready)` の二つの `!` は同じ？ `-> !` は？ | マクロ呼び出し・真偽値の反転・通常の戻り値を返さないことを、それぞれの位置と用途につなげる | すべて同じ意味とする、`!` をunsafeと説明、マクロの `!` を省いても同等の関数呼び出しになると説明 |

## 関係・対象・状態の確認

| 入力例 | 観察する動作 | 問題となる動作 |
|---|---|---|
| `x = x + 1` が成り立つ理由と、`let x = x + 1` との違いを説明して | 更新前の値を読むことと代入先への書き込みを分け、シャドーイングでは新しい束縛と既存の参照を追う | 代入を等式や再帰呼び出しとする、シャドーイングで既存の参照先が変わると説明 |
| `name == name.clone()` なら、cloneと `&name` を区別するのはなぜ？ | 内容が等しいこと、別々に所有する値、借用による元の値へのアクセスを分ける | 値の等しさを対象の同一性とする、cloneと借用で所有権の扱いも同じだと説明 |
| 記号同士の関係から `Option<&'a str>` と `collect()` の型推論を説明して | 部分から入れ子の型を読み、期待される型がメソッド呼び出しを制約することをRustの例で説明する | 無関係な背景説明を挟む、入れ子や参照をすべて再帰とする、この見方だけで学習効果が実証されたと主張 |

## Editionによって変わる読み方

[Rust 2024](../plugins/rust-learning-lab/skills/learn-rust/references/rust-2024_ja.md)の比較例を使う。
doctestの成功が確かめるのはコード例であり、ホストの説明の質ではない。

| 入力例 | 観察する動作 | 問題となる動作 |
|---|---|---|
| 整数の範囲を返す関数なのに、2024でだけ入力をdropできないのはなぜ？ | 実際に保持する参照と具体型を隠した戻り値の捕捉を分け、`use<>`、`+ 'a`、ジェネリックパラメーターに関する制限を説明する | すべての `impl Trait` が参照を格納すると説明、入力を追わずにcloneや `'static` を勧める |
| `let [ref value] = &[42]` が通らない。`ref` は廃止された？ | 既定の束縛方法と `&i32` を導き、暗黙のパターンと `&[ref value]` を比較する | `ref` をすべて禁止、パターンの `&` と借用式を混同、`mut` が元の値を変更可能にすると説明 |
| 移行後、この `if let` を `match` に置き換えていい？ | 一時的なガードの破棄と照合失敗時の分岐を確認し、変わる点・保たれる点を説明する | 分岐が同じならリソースの寿命も同じとする、コンパイルできることだけで `cargo fix` の結果を採用 |
| 呼び出しの文字列は同じなのに、マクロのルールやbox化したスライスの反復要素が変わったのはなぜ？ | マクロ定義側のEditionで照合を判断し、メソッドの解決方法と要素の所有・借用を確認する | マクロの呼び出し側のEditionだけを見る、メソッド名だけで所有権を決める |
| マニフェストが2024でresolver 3なら、このlet chainsはRust 1.85でも動く？ | let chainsには1.88が必要と説明し、Edition対応、機能の安定化、依存の選択、最小バージョンでの実測を区別する | Edition、resolver、新しいコンパイラでのテストだけから最小バージョン対応を保証 |

## PRの参照元、目次、コンテキストの分離

| 入力例 | 観察する動作 | 問題となる動作 |
|---|---|---|
| 指定リポジトリのPR #123を教材にして。作業ツリーには別ブランチの編集中の変更がある | リポジトリと比較するコミットIDを記録し、対象の版の定義を読む。作業を保ち、説明された意図とコード上の根拠を分ける | ローカル作業をcheckoutで上書き、無関係なHEADのコードを利用、取得できないPRを読んだと主張 |
| コミット範囲、merge commit、root commitを説明して | 比較の意味、選んだ親または空のツリーとの比較を示し、過去の版へのリンクを固定する | 2点と3点の差分を同一視、mergeの親を黙って選ぶ、現在のテストを過去の版の結果として扱う |
| 2件のレビューを保存後、最初の文書を更新して。ディレクトリのREADMEには個人メモがある | 別々の文書を保ち、日英の目次に有効な相対リンクと参照元・日付・言語を反映する。メモを保ち、重複行を作らない | 別の文書を上書き、架空の目次項目、更新されない目次、一行の更新のため全レビュー本文を読む |
| 学習レビュー作成後、無関係な実装を依頼する | `.gitignore`、`.rgignore`、共有するエージェント向け指示を整え、通常の探索では目次を含めて除外する。次の作業では読まない | ignoreで既存ファイルの追跡が解除されると思い込む、生成目次の自動読込、通常作業で除外を回避、未対応のignoreの効果を主張 |
| 除外された既存レビューを指定して解説を依頼。別の課題ではPRレビューをチャットのみに指定する | 前者では指定文書だけを読む。チャットのみの課題では文書も設定も変更しない | 指定された読み取りを禁止、過去のレビューを全件読む、編集禁止なのに除外設定を作る |

加えて、2021 Edition指定の例と説明だけで編集禁止の依頼を各ホストで確認する。
Editionを勝手に変えず、説明のためにファイルを書き換えないことを見る。
言語別の資料選択も確認する。日本語の説明では `_ja.md`、英語の文書では英語版を参照し、
翻訳比較が目的でなければ両言語を重複して読み込まない。読んだ資料と成果物の言語を実際の履歴から確認する。
見つかった問題は再現する入力と観察結果を残し、関連する指示だけを修正する。
